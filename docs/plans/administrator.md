# Админка и остатки

Дата: 2026-10-28. Реализация разрешена пользователем; локально, без публикации.

Результат: `/administrator`, вход сотрудника, список и детали заявок,
изменение состава до доставки, комментарии и история, статусы, каталог с ценой,
остатком и скрытием позиций. Изменения защищены сессией, Origin и версиями.

## Контракты и решения

- Учётные записи/сессии принадлежат заявкам. Каталог проверяет сессию через
  HTTP API заявок, не читает таблицы сотрудников. Пароль — Argon2id, случайная
  cookie, в SQL только SHA-256 токена, срок 72 часа. Secure по умолчанию;
  явное исключение для локального HTTP задаётся настройкой разработки.
- Первая учётная запись и сброс: локальная CLI читает пароль из файла,
  обновляет хеш и отзывает сессии одной транзакцией; никаких паролей в argv.
- Каталог владеет остатками. Новые и существующие товары получают остаток 0
  до явного ввода сотрудником. Публичное оформление остаётся без резервирования.
- При `created → delivery` заявки вызывают ограниченный SQL API каталога
  в своей транзакции. Это расширение существующего SQL-контракта общей БД:
  атомарность статуса и списания без распределённой транзакции, но зависимость
  от общего PostgreSQL. Прямые права записи в товары заявкам не выдаются.
- Каталог блокирует позиции в стабильном порядке и списывает весь состав,
  только если хватает каждой позиции. Версия заявки и блокировка защищают
  от повторной отправки; версия товара меняется также при списании.
- Состав меняется только в `created`; старые позиции сохраняют снимок цены,
  добавленные получают текущую цену. История сохраняет предыдущий снимок.
  Комментарии разрешены после отправки. Отмена требует комментария и не
  возвращает остаток автоматически: физический возврат здесь не реализуется.
- Удаление товара в UI — скрытие, чтобы сохранить идентификаторы и историю.

## Фактическая проверка 2026-10-28

Прошли test (race), lint, build, test:integration и test:browser.
Chromium проверил вход/выход и сохранение сессии после reload, правку остатка
и состава, доставку с однократным списанием, историю, создание/скрытие товара,
экранирование комментария и отсутствие overflow страницы на 390 px.
Старые сценарии оформления также проходят. В текущем контейнере использованы
ранее установленные библиотеки из `.tmp/browser-libs` и локальный fontconfig;
новая сборка dev image в этой задаче не проверялась.

PostgreSQL: 12 конкурентных отправок одной заявки списывают один раз;
две заявки на недостаточный общий запас дают один успех; нехватка любой
позиции не меняет ни заявку, ни товары. Ошибка истории после вызова каталога
откатывает уже выполненное списание. CLI-сброс меняет пароль и отзывает сессии.
Проверены запрет чужих SQL-прав, CSRF, истечение/отзыв/блокировка, отказ auth.
Повтор миграций сохраняет тестовые данные. Test DB и роли удалены стендом.

Новые миграции применены к dev без сброса товаров и заявок.
Пользовательская учётная запись не создавалась; рабочие API нужно перезапустить
через `mise run dev` после остановки старого запуска. Доступ настраивается
по README. Production hosting, HTTPS, CI и возвраты остаются вне этого шага.
