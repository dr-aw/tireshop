# Серверный подбор каталога

Задача 2026-10-29: фильтры витрины и админки используют общий backend каталога.
Публичная выборка всегда ограничена опубликованными товарами; административная
защищена существующей сессией. Записи и владельцы данных не меняются.

- [x] Общий валидатор поиска, характеристик, диапазонов, сортировки и пагинации;
  параметризованный SQL, стабильная сортировка, общее число результатов.
- [x] Справочники значений из БД по категории: публичные без скрытых товаров,
  административные с ними. Пустые значения не выдавать как характеристики.
- [x] Витрина: серверная страница, фильтры шин/дисков, сброс, загрузка/ошибка,
  параметры в URL, Back/Forward, без полной загрузки каталога.
- [x] Админка: те же характеристики, поиск, цена, наличие и видимость;
  сохранить выбор колонок и сортировку, сбрасывать страницу при смене фильтра.
- [x] Проверки API на синтетических данных: сочетания фильтров, категории,
  границы/ошибки, скрытые товары, порядок и страницы. Проверки браузером URL,
  возврата, корзины, мобильного вида и админки; test/lint/build.

Справочники зависят от категории и доступа, а не от остальных выбранных фильтров:
это позволяет менять любой параметр даже при пустой выдаче. Новые индексы
добавлять по результатам измерений, ожидаемый объём первой версии — 2000 товаров.
Ручная сверка спорных товаров передана сотрудникам и не является задачей разработки.

Результат: реализован общий backend и два интерфейса. Схема не менялась.
Test/race, lint, build, шесть браузерных сценариев и PostgreSQL integration
прошли на временной test DB. Проверены числовые/текстовые сочетания, скрытые
товары и справочники, ошибки параметров, порядок/страницы, URL/Back/Forward,
сохранение корзины и оформление. Desktop/mobile снимки просмотрены;
горизонтального переполнения на 390 px нет. Markdown и diff проверены.
Пользовательский dev продолжает обслуживаться старым Go API (новый endpoint
справочника возвращает 400); нужен перезапуск mise run dev в контейнере dev.
