# Подбор витрины по диаметру и размеру

Дата: 2026-11-10. Реализация разрешена пользователем по
[плану](../plans/storefront-selection-v1.md).

Каталог сохраняет владение products/tyre_specs/wheel_specs. Админка и старые
параметры API сохраняются; новый интерфейс витрины выделен отдельно.
`radius` означает посадочный диаметр в дюймах. В обеих specs-таблицах это
stored generated column: у шины из исходного size, у диска из diameter_inches.
Независимой записи radius нет. Прежние столбцы остаются для совместимости.

Новая immutable-функция tyre_size_key_v1 нормализует только распознанные размеры.
Исходные size/marking не изменяются, неизвестные значения остаются неизвестными.
Дюймовая ширина получает два знака после точки (7.50R16), метрическая — целое
число. Размер с неизвестным профилем не получает выдуманный профиль.
Связь диаметра и размера определяется товарами, отдельный справочник не нужен.

Индексы начинаются с radius и продолжаются размером и product_id. Новая
выборка использует индексированные столбцы непосредственно; список сохраняет
параметризованный общий валидатор. Новый endpoint selection агрегирует в SQL
радиусы и размеры одним statement. Старый filters сохраняет прежнюю семантику.

Счётчик физических единиц — SUM(stock::bigint * units_per_sale::bigint).
Один товар ограничен существующими CHECK, произведение помещается в bigint,
SUM(bigint) возвращает numeric. unit_count передаётся десятичной строкой:
даже один разрешённый большой stock в комплекте превышает точность JS Number.
Интерфейс форматирует BigInt. product_count и total — количество карточек.

Выпуск: новая миграция, затем backend, затем frontend. Добавление столбцов
проекции только в конец сохраняет старое чтение и Save. Откат приложения
не требует удаления столбцов. Автоматического destructive down нет.
