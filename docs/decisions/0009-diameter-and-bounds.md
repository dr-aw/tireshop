# Посадочный диаметр и диапазон ассортимента

Дата: 2026-11-10. Пользователь разрешил миграции 00006 и 00007.
Дополняет [ADR 0008](0008-storefront-selection.md).

00006 переименовывает generated radius в diameter обеих specs-таблиц.
ALTER COLUMN RENAME сохраняет значения, generated-выражения и существующие
индексы. В product_details прежний diameter становится общим для шин/дисков,
radius остаётся совместимым псевдонимом. Исходные size и diameter_inches,
а также rim_diameter_inches шин сохраняются.

Важно: плоский DTO редактора продолжает отдавать diameter только для дисков.
У шин по-прежнему rim_diameter; catalogdata.Select явно сохраняет эту проекцию.
Это позволяет прежнему редактору повторно отправлять DTO без ложной ошибки
«поля диска у шины». Новое общее SQL-поле используется подбором, а не становится
вторым источником редактирования размера шины.

Основной параметр списка/selection — diameter при явной категории. radius и
rim_diameter остаются совместимыми фильтрами, ограничения сочетаются AND.
Selection отдаёт diameters и временный идентичный radii для старых клиентов.
Frontend пишет diameter; старые URL преобразуются при чтении состояния,
а при следующей навигации записывается новый параметр. Противоречивый legacy
параметр не теряется: показывается снимаемое ограничение.

00007 добавляет CHECK diameter IS NULL OR diameter BETWEEN 11 AND 25 обеим
таблицам. Это диапазон ассортимента, включая границы и дробные значения.
NULL/нераспознанный текст остаются допустимыми, проверка не является строгой
валидацией всего синтаксиса size. Если исходный каталог нарушает диапазон,
миграция отказывается целиком, не переписывая данные. Runtime/admin получает
422 с пояснением границ; транзакция редактирования откатывается полностью.

Выпуск: миграции → новый catalog API → frontend. Старый бинарник 00005,
который обращался непосредственно к specs.radius, не совместим с переименованием
этих столбцов. Псевдоним SQL-проекции сохраняет старые чтения проекции, но не
заменяет обновление бинарника. Для первого production применить всю историю
до 00007. Автоматического destructive down нет.
