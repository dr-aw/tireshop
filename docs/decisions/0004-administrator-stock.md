# Администрирование и атомарное списание

Дата: 2026-10-28. Реализовано по поручению пользователя об админке и списании.
Расширяет [границы сервисов](0001-catalog-and-requests.md) и
[собственный вход](0002-admin-auth.md).

## Решение

Остатки принадлежат каталогу. Сервис заявок не получает UPDATE на товары.
Каталог предоставляет команду `catalog.dispatch_v1(uuid[], bigint[])` —
версионированный SQL API общей PostgreSQL. Это узкая SECURITY DEFINER-функция
с фиксированным search_path, без динамического SQL и без EXECUTE для PUBLIC.
Она проверяет вход, блокирует товары в порядке ID, проверяет все количества
и списывает их, увеличивая версии товаров. Пропавшая позиция или нехватка
отменяют операцию целиком. Скрытие позиции на витрине не запрещает отправку
уже оформленной заявки, если физического остатка хватает.

Заявки блокируют свою строку и сверяют ожидаемую версию. Переход в доставку,
вызов каталога, новая версия и история фиксируются одной транзакцией.
Повтор с прежней версией возвращает 409; после потери ответа нужно перечитать
заявку. Это оптимистическая блокировка, не сохранённый ответ на ключ повтора.

Это сознательная связанность общей БД: SQL-команда не требует живого процесса
каталога, но требует его схемы и совместимого контракта. При разделении БД
понадобится протокол с журналом операций и восстановлением;
просто заменить функцию HTTP-вызовом внутри транзакции нельзя.

Состав редактируется до доставки. Существующие позиции сохраняют снимок
названия и цены, новые получают текущие данные каталога. История хранит
снимки до/после, сотрудника, время и комментарий. Комментарий покупателя
остаётся исходным; сотрудник добавляет свои комментарии.
Отмена не доказывает физический возврат и не восстанавливает запас автоматически.
Частичные отправки и отдельный процесс возвратов пока не реализованы.

## Доступ

Вход и сессии принадлежат заявкам. Каталог проверяет cookie через HTTP
`GET /api/admin/session` заявок на каждом административном запросе.
Таблицы сотрудников каталогу недоступны. При недоступности проверки — 503.
Изменения требуют разрешённого Origin и заголовка X-Admin-Request;
CORS для посторонних сайтов не включён.

Пароли: Argon2id, 19 MiB, 2 прохода, параллелизм 1, случайная соль 16 байт.
В БД сессий — SHA-256 случайного 32-байтового токена; cookie HttpOnly,
SameSite=Strict, Secure по умолчанию. Срок 72 часа без продления.
Локальная задача dev явно отключает Secure для HTTP.
Лимит входа: 5 попыток за минуту на логин и socket peer,
не более двух вычислений хеша одновременно, ограниченная карта счётчиков.
Лимиты в памяти процесса; политика reverse proxy/нескольких инстансов
остаётся задачей production-развёртывания.

Создание/сброс выполняется локальной CLI с административным подключением.
Она читает приватный файл пароля, меняет хеш и отзывает сессии транзакционно.
Advisory lock согласует сброс с конкурентным входом, чтобы старый пароль
не создал сессию после отзыва. Процедура — в [README](../../README.md).

## Проверка

В отдельной test DB проверены права, auth/CSRF, истечение и отзыв,
блокировка учётной записи, отказ проверки сессии, история и снимки,
конкурентные списания, нехватка, откат при ошибке истории и CLI-сброс.
Chromium проверил основной сценарий и безопасный вывод комментария.
