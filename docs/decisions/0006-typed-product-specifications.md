# Отдельные характеристики шин и дисков

Дата: 2026-10-29. Пользователь разрешил миграцию и изменение фильтров.

## Решение

`catalog.products` хранит общие данные, цену, запас, единицу продажи, публикацию
и версию. `tyre_specs` и `wheel_specs` хранят характеристики своего типа.
У товара сохраняется один UUID для заявок, снимков, истории и фотографий.
Сервисы и контракт заявок не меняются. Отдельные сервисы по типам товара не нужны.

PK характеристик — product_id, составной FK (product_id, kind) ссылается на
уникальную пару товара. CHECK фиксирует тип каждой таблицы; нельзя создать
характеристики диска у шины или одновременно оба типа. DELETE товара каскадно
удаляет характеристики. Минимальный товар без заполненных характеристик
допустим; неизвестные значения проецируются как NULL/пустая строка.

`catalog.product_details` — проекция для чтения и фильтрации, не вторая копия
характеристик. HTTP details остаётся плоским для совместимости карточек.
Права записи имеет только каталог; сервис заявок не читает новые таблицы.
Редактирование через catalogdata.Save выполняется в транзакции с проверкой
версии товара. При смене типа старые характеристики удаляются, новые записываются;
при ошибке вся операция откатывается. Frontend очищает несовместимые поля.

## Размеры и единицы

У диска diameter_inches/width_inches — дюймы, offset_mm/center_bore_mm — мм.
PCD остаётся исходным нормализованным обозначением (например 10x335), маркировка
сохраняется отдельно. Преобразование PCD в число отверстий и окружность
не требуется для точного фильтра и в эту миграцию не включено.

У шины size — исходная строка и единственный редактируемый источник размера.
Generated columns width_value/width_unit/aspect_ratio/rim_diameter_inches
вычисляются immutable-функцией. Разбираются только полные формы:

- 295/80R22.5 → 295 мм, профиль 80%, посадочный диаметр 22,5 дюйма.
- 165R13 → 165 мм, профиль неизвестен, посадочный диаметр 13 дюймов.
- 11R22.5 и 7.50R16 → ширина в дюймах, профиль неизвестен.

Пробелы, регистр R и десятичная запятая нормализуются только для разбора,
исходный size не переписывается. Прочие обозначения остаются текстом,
производные параметры — NULL. Не извлекаем размеры из названия/описания.
Чтобы поменять алгоритм, нужна новая миграция с пересчётом generated columns.

Ширина шины в фильтре передаётся с единицей (`tyre_width=295 mm` / `11 in`),
поэтому разные единицы никогда не сравниваются как одинаковые числа.

## Перенос и эксплуатация

Миграция 00004 переносит старые значения, затем удаляет специализированные
столбцы из products. Все снятые значения дополнительно сохраняются в
`specs_migration_archive`: это неизменяемый для runtime снимок переноса,
а не используемый приложением источник данных. Некорректно размещённые старые
свойства не превращаются в характеристики другого типа и остаются в архиве.

В проверенной dev до миграции числовая ширина/диаметр у шин не были заполнены;
у дисков заполнены обе величины. Проверка на заполненной схеме версии 3
сравнивает все прежние значения, единицы продажи, запас, версии и фото.

Старая версия backend несовместима с новой схемой: при развёртывании нужен
согласованный запуск новой версии после миграции. Перед dev-переносом создаётся
локальная копия каталога; автоматический destructive down не предусмотрен.
Восстановление из копии допустимо только с учётом записей после миграции.

## Фильтры

Без категории доступны только общие поля: бренд, модель, состояние, год,
цена, наличие; в админке дополнительно запас и видимость. Размерные фильтры
требуют явной категории и сбрасываются при её смене. Справочники строятся
из соответствующих таблиц через проекцию, скрытые товары не попадают в публичные.
